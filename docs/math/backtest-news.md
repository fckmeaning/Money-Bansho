# Тон заголовков и полураспады репутации на реальной истории

Скрипт: [`scripts/backtest-news-tone.mjs`](../../scripts/backtest-news-tone.mjs). Прогон 2026-11-28.
Это отчёт, а не ворота. Ничего здесь не обещает цену акций.

## Кратко

| Вопрос | Результат | Решение |
|---|---|---|
| Согласуется ли тон словаря с движением цены в те же дни | Да: после дней с положительным тоном избыточная доходность за день публикации и следующий на 83 б.п. выше, чем после дней с отрицательным [51; 112]; без заголовков про саму цену 36 б.п. [12; 60] | Словарь тона оставлен |
| Предсказывает ли тон следующие 1 / 5 / 20 сессий | Не обнаружено: +1 / +5 / −15 б.п., все интервалы накрывают 0 (на отложенной части тоже) | Прогнозом не называть |
| Лучше ли другие полураспады, чем в `HALF_LIFE_DAYS` | Вне выборки ни один вариант, выбранный на обучении, не отличим от кода (p = 0.90 / 0.63 / 0.23) | **Константы не менялись** |
| Полураспад отдельного типа | Из 15 сравнений с кодом p < 0.05 в одном; после поправки FDR ни одно не значимо (q ≥ 0.18) | **Константы не менялись** |

## 2. Метод

Классификация, тон, дедупликация и веса взяты из кода (`classifyEvent`, `dedupeEvents`, `evidenceWeight`).

**Без заглядывания вперёд.** Почти все `pubDate` в архиве это только дата (07:00 или 08:00 UTC). Поэтому сигнал на
конец сессии `i` использует заголовки с датой **строго раньше** дня сессии, а предсказываемая доходность начинается
после её закрытия:

    AR_t = ln(P_t / P_{t−1}) − ln(M_t / M_{t−1})
    y_h(i) = Σ AR_t,  t = i+1 … i+h,   h = 1, 5, 20
    S_H(i) = Σ w·s / (Σ w + 3)          = (R − 50) / 50 из docs/bansho-math.md
    w = T(тип) · Q(источник) · K(издания) · 2^(−возраст / H),  возраст ≤ 90 дней

**Эффект тона.** Для каждого дня публикации средний тон его заголовков; нулевые дни отброшены.

    Δ = mean(y | тон > 0) − mean(y | тон < 0), в базисных пунктах

«Те же дни» это сумма `AR` за сессию дня публикации и следующую: описательная связь, не предсказание (заголовок мог
пересказывать уже случившееся движение). Проверка чувствительности выбрасывает заголовки со словами про цену
(`stock`, `shares`, `surge`, `plunge`, `rise`, `fall` и подобные).

**Полураспады.** Показатель: средний по компаниям ранговый коэффициент Спирмена `rho(S_H, y_h)` внутри компании.
Варианты: коды по типам (`code`), они же ×0.1, ×0.25, ×0.5, ×2, единый H = 1, 3, 7, 14, 30 дней, без затухания.

* Обучение: первые 60 % дней, хвост в `h` сессий вырезан, чтобы цели не заходили в отложенную часть.
* Проверка: вариант с лучшим `rho` на обучении сравнивается с `code` на отложенной части.
* По типам: то же отдельно для сигнала из заголовков одного типа, H из {1, 3, 7, 10, 14, 21, 30, 45, 90}, h = 5 и 20.
* Интервалы 95 %: бутстрэп 30-дневными блоками, общими для всех компаний, 500 повторов, seed фиксирован;
  p двусторонний по перцентилям; поправка Бенджамини-Хохберга внутри каждой таблицы.

## 3. Результаты

### 3.1 Эффект тона, Δ в б.п. [95 %]

| Цель | Все дни | Отложенная часть |
|---|---|---|
| те же дни (2 сессии) | **+83 [51; 112]** | **+111 [55; 165]** |
| те же дни, без заголовков про цену | **+36 [12; 60]** | **+55 [18; 92]** |
| следующая 1 | +1 [−12; 14] | +5 [−13; 22] |
| следующие 5 | +5 [−25; 45] | +0 [−57; 68] |
| следующие 20 | −15 [−118; 89] | −70 [−206; 93] |

Все дни: 2247 положительных и 1537 отрицательных; отложенная часть: 1065 и 626.

По типам (следующие 1 и 5 сессий, все дни): `leadership` (20 / 20 дней) и `scandal` (8 / 156) слишком малы, не
считались (порог 30 на сторону). Из остальных 12 проверок одна имеет p < 0.05 без поправки: `politics`, 5 сессий,
+181 б.п. [34; 340], 74 / 71 дней, q = 0.19. После поправки это не находка.

### 3.2 Полураспады репутации, rho

`*` q ≤ 0.1 на отложенной части. Колонка «прошлые 5» считает `rho` с доходностью за последние 5 сессий, включая
сессию расчёта.

| Вариант | прошлые 5 | обучение h = 1 / 5 / 20 | отложенная h = 1 / 5 / 20 |
|---|---|---|---|
| **code** | 0.040 | 0.008 / 0.027 / 0.023 | −0.031* / −0.058* / −0.124* |
| code ×0.1 | 0.065 | −0.005 / 0.014 / 0.050 | −0.012 / −0.040* / −0.031 |
| code ×0.25 | 0.056 | 0.002 / 0.017 / 0.026 | −0.024 / −0.050* / −0.037 |
| code ×0.5 | 0.050 | 0.006 / 0.024 / 0.020 | −0.026* / −0.046* / −0.075* |
| code ×2 | 0.034 | 0.006 / 0.024 / 0.018 | −0.028* / −0.063* / −0.157* |
| 1 день | 0.084 | −0.004 / 0.000 / 0.037 | −0.001 / −0.001 / −0.028 |
| 3 дня | 0.083 | 0.000 / 0.016 / 0.052 | −0.005 / −0.023 / −0.042* |
| 7 дней | 0.071 | 0.008 / 0.036 / 0.053 | −0.017 / −0.045* / −0.075* |
| 14 дней | 0.058 | 0.011 / 0.032 / 0.025 | −0.032* / −0.064* / −0.120* |
| 30 дней | 0.039 | 0.005 / 0.020 / 0.003 | −0.040* / −0.083* / −0.174* |
| без затухания | 0.012 | 0.001 / 0.015 / −0.003 | −0.041* / −0.090* / −0.186* |

Walk-forward:

| h | выбран на обучении | rho обучения | rho выбранного на проверке | rho `code` на проверке | разность [95 %] |
|---|---|---|---|---|---|
| 1 | 14 дней | 0.011 | −0.032 | −0.031 | −0.001 [−0.015; 0.014] |
| 5 | 7 дней | 0.036 | −0.046 | −0.058 | +0.013 [−0.029; 0.050] |
| 20 | 7 дней | 0.053 | −0.075 | −0.124 | +0.049 [−0.036; 0.104] |

Как читать:

* Ни один вариант на обучении не значим (все p ≥ 0.05), то есть выбирать было нечего.
* Знак меняется между периодами: слабо положительный на обучении, отрицательный на проверке. Это не сигнал разворота.
  Медленный сигнал (память 90 дней) и перекрывающиеся цели дают всего около десятка независимых 30-дневных блоков на
  проверке; интервалы для длинных H, вероятно, слишком узкие.
* Короткие полураспады теснее связаны с уже прошедшей доходностью (0.084 против 0.040): они свежее отражают, что
  случилось. Репутация по замыслу это память о новостях за 90 дней, а не повтор цены, поэтому это не основание менять
  константы.

## 4. Что изменено

Ни одна числовая константа. `TYPE_WEIGHT`, `HALF_LIFE_DAYS`, `PRIOR_WEIGHT`, словари тона остаются объяснимыми
эвристиками: данные не опровергли и не подтвердили их.

## 5. Что проверить не удалось

* **Полураспад внимания к событию по типам.** При плотном потоке (в среднем около 50 событий на компанию в месяц)
  отклики разных новостей перекрываются и не разделяются. Оценка по редким 8-K есть в
  [backtest-real.md](backtest-real.md), раздел 3.3.
* **Вес новостей 0.3 в индексе внимания.** Выдача ограничена 100 записями на запрос и даёт от единиц до 100 в месяц,
  поэтому число заголовков в этих данных не отражает реальный поток.
* **Веса типов и источников**, отдельно не проверялись.

Ограничения выборки:

* Google News отбирает и ранжирует результаты **на дату запроса**: в архиве могли остаться преимущественно статьи,
  ставшие заметными позже. Это смещение отбора задним числом, устранить его бесплатным источником нельзя.
* Только 19 крупных компаний США, английский язык, один бенчмарк, 28 месяцев (один рыночный режим). Выводы не
  переносятся на другие языки и малые компании.
* 73 % событий имеют тип `other`; тон считается по заголовку словарём.
* Проверено много вариантов; поправка FDR применена внутри таблиц, а не по всему отчёту.

## 6. Воспроизведение

```bash
node scripts/backtest-news-tone.mjs --cache <папка>             # скачивает недостающее (около 7 минут) и считает
node scripts/backtest-news-tone.mjs --cache <папка> --offline   # только расчёт, около 30 секунд
```

Заголовки кэшируются вне репозитория. Новая выгрузка даст другую выборку (поиск Google News не стабилен), поэтому
числа совпадут только на том же кэше. Бары: из `docs/handoff/backtest-data/`, для отсутствующих бумаг из Yahoo.
